# DrainWatch DBMS Files

This folder contains the PostgreSQL database implementation and DBMS lab documentation for DrainWatch.

## Folder contents

- `dbms/schema.sql` — creates all tables, primary keys, foreign keys and constraints.
- `dbms/sample_data.sql` — inserts demo users, ward configuration and a sample complaint.
- `dbms/queries.sql` — 17 example SQL queries covering joins, subqueries, aggregates, grouping and window functions.
- `dbms/views.sql` — creates reporting views.
- `dbms/triggers.sql` — updated timestamp triggers and an opt-in complaint status audit trigger.
- `dbms/indexes.sql` — indexes and an EXPLAIN ANALYZE example.
- `dbms/transactions.sql` — COMMIT, ROLLBACK and SAVEPOINT examples.
- `dbms/er_diagram.md` — Mermaid ER diagram and relationship explanation.
- `dbms/normalization.md` — 1NF, 2NF and 3NF explanation.

## Run in pgAdmin

1. Open pgAdmin and connect to your PostgreSQL server.
2. Create a database named `drainwatch`.
3. Select `drainwatch` and open Query Tool.
4. Run files in this order:
   1. `dbms/schema.sql`
   2. `dbms/sample_data.sql`
   3. `dbms/views.sql`
   4. `dbms/triggers.sql`
   5. `dbms/indexes.sql`
5. Run `dbms/queries.sql` and `dbms/transactions.sql` when you want to test queries and transaction examples.

Run `schema.sql` only once for a fresh database. Most objects use `IF NOT EXISTS` or `CREATE OR REPLACE`, but this is not a migration system.

The password hash is generated by PostgreSQL `pgcrypto` using bcrypt (`crypt` / `gen_salt`). It is compatible with bcrypt verification in the Node.js backend. These are local demo credentials only; change them before any deployment.

## Backend connection

In `backend/.env`, use your own PostgreSQL password:

```env
DATABASE_URL=postgresql://postgres:YOUR_POSTGRES_PASSWORD@localhost:5432/drainwatch
```

The backend expects the table and column names defined in `schema.sql`.

## Important project notes

- Update the sample ward centre and radius in `ward_settings` and the backend `.env` so they represent the same selected project area.
- The backend uses a centre-point radius check. It is a simple project boundary approximation, not an official ward polygon.
- Risk score is a rule-based maintenance-priority indicator, not a flood prediction.
- `triggers.sql` includes an opt-in status audit trigger. The supplied Express backend writes status history itself; leave the opt-in trigger disabled to avoid duplicate history entries.
- `sample_data.sql` requires the PostgreSQL `pgcrypto` extension, which `schema.sql` enables.
